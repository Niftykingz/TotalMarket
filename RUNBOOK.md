# TotalMarket automation runbook

Two recurring Claude scheduled tasks start the runs ("TotalMarket news update" at 08:45, 12:45, 15:45 and 20:45 IST daily; "TotalMarket daily market report" at 20:10 IST on weekdays). Each run starts in a fresh session: work out the slot from the IST time, follow it below, commit the job and data files, and let the GitHub publish queue publish (step 8). A failed run never stops later runs.

Slots (IST): `premarket` 08:45 · `midday` 12:45 · `close` 15:45 · `report` 20:10 · `evening` 20:45.
On weekends and NSE holidays only `midday` runs, as a "Weekend roundup" or "Market holiday briefing"; at every other slot stop without changing anything.

## 1. Prepare
- Attach the repository with `mcp__claude-code-remote__add_repo` (owner `Niftykingz`, repo `TotalMarket`, access `push`), then `git clone https://github.com/Niftykingz/TotalMarket /home/claude/totalmarket` (or `git pull --rebase origin main` if it exists). If `python3 -c "import PIL, numpy"` fails: `pip install --break-system-packages pillow numpy`.
- Check the IST time and whether NSE is open today.

## 2. Scope and rules
Indian retail investors and traders who follow global markets and tech. `category` is one of: markets, tech, startups, policy, global, commodities (see README). Politics only where it moves money; neutral.
Never recommend buying, selling or holding anything; no price targets or tips. Write in your own words (no copied sentences; at most one short quote under 15 words per source). Never invent numbers; omit what you can't verify; give ranges if sources conflict. No logos, no photos of people except Wikimedia Commons files via `people`, no downloaded images.

## 3. What each slot publishes
- **premarket**: lead with "Overnight global wrap" (category global, lead true) with a `table` of overnight moves (Dow, S&P 500, Nasdaq, US 10Y, DXY, USD/INR, USD/JPY or EUR/USD, gold, silver, Brent, WTI, copper, Nikkei/Hang Seng, GIFT Nifty, Bitcoin; omit unverified rows). Add separate stories for gold & silver (global + Indian rates), crude, rupee, key US news/data, and "Results today and what to watch".
- **midday**: market mid-session, rupee, gold/crude moves, results so far.
- **close**: Sensex/Nifty close (points, %), top gainers/losers, sectors and why, results reported today, rupee close, MCX gold/silver. **Before writing the closing wrap, append today's verified closes to `meta.history` (Nifty 50, Sensex, Bank Nifty, with source)** — the pipeline blocks a closing story whose closes are not saved (MISSING_DATA) unless its job has an `index_board` chart. The report slot re-checks those closes against the official NSE file and corrects them if needed.
- **report**: the full Daily market report story (`data/posts/<date>-stock-market-today-sensex-nifty-closing-report.json`) with the `report` object as documented in README (indices with open/high/low/close, caps, sectors, gainers/losers, movers, breadth, FII/DII, IPO listings and what happened after listing, levels with source, what to watch). Confirm today's closes in `meta.history` (already appended in the close slot; correct them from the NSE file if they differ; keep last 30).
- **evening**: tech and startup news, IPO subscription status, Europe/US open, commodity moves; refresh `data/results.json` for the next 7–10 days (remove entries >2 days old).
- **IPO daily (every market day, published in the `evening` slot; on weekends/holidays inside the `midday` roundup):** one story `data/posts/<date>-ipo-today-<main-names>.json`, category `startups`, `coverLabel: "IPO daily"`, symbol `growth`, editionLabel `<Ddd D Mon> · IPO daily`. Voice: a friendly finance teacher talking to beginners ("Namaste investors, welcome to today's IPO class") — warm and energetic, but education only: never say apply, skip, avoid, "good IPO" or give targets. Body in this order: (1) **Open now** – each mainboard IPO open today: price band, lot size and minimum amount, issue size split into fresh issue vs OFS, retail quota, day-wise subscription by category (QIB/NII/retail) with time and source, close and listing dates; (2) **Listed today** – issue price, listing price and %, how it traded after listing (high/low or latest, % vs issue) and the final subscription; (3) **Today's concept** – one IPO idea explained with a worked example using real numbers from today's IPOs (rotate: fresh vs OFS, GMP, anchor investors, QIB/NII/retail quotas, allotment lottery, price band and cut-off, lock-in expiry, P/E vs peers, use of proceeds, red flags in the RHP, ASBA/UPI mandate, SME vs mainboard); (4) **Coming up** – IPOs opening, closing, allotting and listing in the next 5 sessions; GMP only as a range with the warning that it is unofficial; (5) a "Key takeaway" line ending with "This is education, not a recommendation." Add a `table` "IPO dashboard" with one row per IPO (status, price band/lot, key dates, listing gain). SME IPOs only when unusually large or newsworthy. Tags include "IPO today", "Upcoming IPO", "IPO GMP today" and "<Name> IPO", "<Name> IPO subscription status", "<Name> IPO listing".
- **IPO hub data (`data/ipos.json`, every slot that has IPO news; always in `evening` and the IPO daily):** keep one entry per mainboard IPO from the day its dates are announced until about 10 sessions after listing (then delete it). Fields: name, slug, segment, exchange, business (one sentence), open, close, allotment, listing (ISO dates), priceBand, lot, minAmount (lot × upper band), issueSize, fresh, ofs, subscription {asOf, total, qib, nii, retail, employee, shareholder, source{name,url}}, gmp {value range, asOf}, issuePrice, listingPrice, listingGainPct, afterListing (one line: day-1 close or latest vs issue), note, sources. Status (open/upcoming/closed/listed) is computed from the dates, so keep dates correct. Set `listed: true` with listing price once a company lists. Update top-level `asOf` and `updatedAt`. Omit anything unverified. This feeds /ipo/, /ipo/<slug>/ pages and the "IPO watch" box.
- **Company pages** (/stock/<slug>/) are built automatically from every story's `companies` field and `data/results.json`. Always fill `companies` with the exact company name and NSE ticker (US tickers for US firms) so stories land on the right page; use the same spelling every time (e.g. "Eternal", "Reliance Industries", "HDFC Bank").
- **FII/DII data (`data/fii_dii.json`, every `report` slot; also premarket if the previous day's figures are newly out):** add the latest provisional cash-market day at the top of `days` as {date, fii{buy,sell,net}, dii{buy,sell,net}} in ₹ crore (never duplicate a date; keep last 30), refresh `month` (label like "October 2026 (to 21 Oct)") and `source`, set `updatedAt`. Feeds /fii-dii-data/. The /top-gainers-losers-today/ page reads the newest `report` story, and /live/ lists the day's stories automatically.
- **Global indices (`data/global.json`, every `premarket` slot; refresh India rows at `close`):** for each region (India, United States, Asia-Pacific, Europe when verified) list {name, value, change, pct, asOf ("Tue 20 Oct, close" or "Wed 21 Oct, intraday (source, time IST)"), type "close"|"intraday", source{name,url}}. Use closing levels whenever available; mark intraday figures as intraday with their time. If two sources disagree on a level, leave that row out and note it under "Needs verification". Feeds /global-indices/.
- **MCX and silver (`data/rates.json`):** with gold rates, refresh `mcx` {asOf, contract, gold, goldChangePct, silver, silverChangePct, source} and `silverRetail` {date, range[low, high] per kg, note, source}. Feeds /gold-rate-today/ and /silver-rate-today/. The /nifty-50/ page reads `meta.history` and the newest report automatically.
- **Corporate events (`data/corporate_events.json`) — MUST be refreshed EVERY DAY:** in the `evening` slot on market days and in the `midday` roundup on weekends and holidays (and in any run where `build.py` prints a corporate-events WARNING). Add confirmed dividends (amount, ex-date, record date), bonus issues, splits, buybacks, board meetings and major announcements for the next 7–10 days, plus results already reported today. Each event: {date, company, ticker, type ("Dividend" | "Bonus" | "Split" | "Buyback" | "Board meeting" | "Financial results" | "Announcement"), detail (one factual line), exDate, recordDate, noticeUrl, source{name,url}}. Put the official NSE notice link (an `nsearchives.nseindia.com` PDF or the filing page) in `noticeUrl` only when you actually found it; otherwise leave it empty and the page links to the right NSE filings page with "per <source>". Delete events older than 14 days. Results dates from `data/results.json` appear automatically, so don't repeat them here. Always set `updatedAt` to now, even if nothing new was found (then say "no new corporate events" in the run report).
- **Market breadth (`report.breadth` in the daily report):** always fill advances, declines, unchanged, highs52, lows52, upperCircuit, lowerCircuit, wealth and exchange from a named source; leave any you cannot verify out (the home card then shows "Unavailable", never an old number).
- **Market holidays (`data/market_calendar.json`) — EVERY YEAR:** the file holds one entry per year in `years` ({year, holidays[{date,name}], weekendHolidays, specialSessions, sources, checked}); each year gets its own page `/stock-market-holidays-<year>/` automatically. From 1 December, every run checks whether NSE has published next year's trading-holiday circular; as soon as it is out, add the new year (dates checked against NSE's holiday page and two published copies), keep the old year, and publish a story "Stock market holidays <next year>: full NSE and BSE list" (category markets, Boss Piggy explains). `build.py` prints a WARNING when the next year is missing in December or the current year is missing at all; fix it in that run. Also update the current year when NSE changes a holiday or announces Muhurat trading timings, and set `checked`.
- **Festivals**: on major festivals, one festive educational piece (`palette: "festive"`, `coverLabel`, `symbol: "diya"`).

- **Gold & silver rates (premarket, midday, close, and the weekend/holiday midday):** refresh `data/rates.json`. `benchmark` = latest IBJA rates from https://ibjarates.com/ (gold 999/995/916/750/585 per 10 g, silver 999 per kg, `date`, `session` AM/PM; set `note` if IBJA skipped a day). Append the day's PM rates to `history` once per date (keep last 30). `cities` = shop rates per 10 g for 24K/22K from one same-day source, named in `citySource` with time; add cities only when that source covers them. `retailRange` = low–high 24K/22K shop rates across the day's sources, with links. Never copy an old or cached page: check the date on the source. Omit a field rather than guess. `updatedAt` = now.

## 4. Research
Several WebSearch calls in one turn ("standard", "extended" if thin) plus WebFetch. Prefer NSE/BSE, SEBI, RBI, PIB, filings, Economic Times, Business Standard, Moneycontrol, Mint, Reuters, CNBC, Kitco, CME FedWatch, Trendlyne/NiftyTrader for FII/DII. Check the newest ~60 posts so you don't repeat stories.
**Official NSE data (use first for index, sector, breadth and FII/DII numbers).** The "Collect NSE market datasets" workflow runs at 16:15 IST on weekdays and commits the raw NSE responses to `data/market_snapshots/<YYYY-MM-DD>/` (`api_allIndices.json.gz`: 139 indices with close, change, %, open/high/low, advances/declines and the close a week earlier; `api_fiidiiTradeReact.json.gz`: provisional FII/FPI and DII buy/sell/net). If today's folder exists, print the quotable lines with `python3 -m pipeline dataset-lines data/market_snapshots/<date>/api_allIndices.json.gz --grep "NIFTY REALTY"`. Use the printed `source` (`dataset` + `sha256`, plus id, name, url `https://www.nseindia.com/api/allIndices`, published = the payload time) and copy the whole printed line as each figure's `evidence`. The pipeline rebuilds those lines from the raw bytes and checks the hash, so never edit snapshot files. NSE values are ungrouped (`22600`); use them as printed. Market-wide top-level advances/declines in allIndices count index memberships, not stocks: for breadth use an index's own advances/declines (e.g. NIFTY 500). NSE's Nifty 50 constituent endpoint returns 404 to automated access; take gainers/losers from named secondary sources.

## 5. Write stories through the strict pipeline (only meaningful, verified developments, at most 9 per slot; one file for `report`)
**Never write `data/posts/*.json` by hand.** For each article write a job file `pipeline/inbox/<YYYY-MM-DD>-<keyword-slug>.json` (format: `pipeline/README.md`, example `pipeline/examples/close-story-job.json`):
`collection` (sources with https URL and published time; every figure with id, label, value, change/pct if used, as_of, source id and the exact evidence text from that source containing the value; mark the story's main figures `key: true`; worked-example numbers in `examples`), `graphic` (headline + cover fields) and `article` (all post fields below, including `hi`). Then run `python3 -m pipeline run pipeline/inbox/<file>.json`. It runs DATA_COLLECTION → DATA_VERIFICATION → GRAPHICS_GENERATION → ARTICLE_WRITING → FINAL_QA and writes the post only if everything passes. If a stage FAILS, fix the job (add evidence, remove the unverified number) and run again, or leave the story out and list it under "Needs verification". Updating an existing story = edit its job file (or create one for an older story) and re-run; set `updatedAt`, `status`, `changeNote` in `article`.
**Data-driven graphic (required for financial news).** Every IPO, stock-move, earnings, RBI-rate, commodity, forex, market-index and global-markets story needs a `chart` in the job's `graphic`, built only from verified figures in `collection` (layouts and minimum content: `cover_templates_v2.py`; real examples: `pipeline/examples/make_v2_dryrun_jobs.py`):
- market index / midday / close / preview → `index_board` (Sensex & Nifty value + change, plus midcap/smallcap/breadth chips)
- global markets → `global_bars` (3+ indices with %)
- gold, silver, crude → `commodity_card` (price + change, comparison tiles)
- rupee → `forex_card` (now vs previous close, change)
- RBI rate decision → `policy_rate` (roles before / after / change)
- single stock move (incl. reaction to results) → `stock_move`
- IPO subscription → `ipo_subscription` (role total + categories); IPO listing → automatic listing card from `data/ipos.json`
- results → `earnings_v2` (revenue and profit with change and, if verified, the comparison values)
Each chart item's numbers must come, at face value, from the figures whose label shares a word with the item label (e.g. item "Realty" ↔ figure "Nifty Realty change %"); if the words differ, list the ids in the item: `"figures": ["bps"]`. The cover headline's numbers must be figures shown in the chart, and the article title/dek must share a figure with it. **No generic illustration for financial news**: if the figures are missing the pipeline fails with MISSING_DATA — do one more research pass for the missing figures, update the job and `python3 -m pipeline retry`; if still unavailable, leave the story out and list it under "Needs verification". Illustrations remain only for explainers, festivals, tech and funding news.
Post fields: Fields per README: title, dek, category, lead (exactly one true per update; unset older ones), edition `<date>-<slot>`, editionLabel `Wed 21 Oct · Pre-market brief`, publishedAt (now, +05:30, one minute apart), readMins, body (array), indiaImpact (required), globalImpact, optional table, **coverHeadline** (3–6 words on a verified number), stat, statLabel, symbol (most specific; vary), flags, companies, optional people (Commons only), seoTitle (search-style, dated for daily prices), tags (6–10 real search phrases), sources.

### Voice: teach, don't just report
Write like a friendly teacher walking a beginner through the news. Open with what happened in one plain sentence, then explain why it happened and what it means for an ordinary investor or saver. Define every piece of jargon the first time (e.g. "FII — foreign institutional investors, big overseas funds"). Where a number matters, add a short worked example with real figures ("a ₹10 lakh home loan at 8.5% means…"). End the body with a one-line "Key takeaway" paragraph. Still no tips or recommendations.

### Editorial rules (accuracy, freshness, transparency)
- **Record times separately:** `publishedAt` is when we publish; write the event time in the body ("at 3:00 pm", "on Monday"). Label every market figure with its as-of time and whether it is live, delayed, or a close. If markets are closed, say so and use the latest verified close with its date. Never mix today's live figures with an earlier close without dates.
- **Cover data (`figures`) for data covers:** for every results story add `figures`: [{company, label ("Net profit", "Revenue from operations"), value ("₹349.22 cr"), change ("+9.7%"/"−24%"), vs ("vs Q2 FY26"), period ("Q2 FY27 (Jul–Sep 2026) · consolidated")}] using only verified numbers; the cover then becomes an earnings card. Closing/report stories get an index chart automatically from `meta.history` (so append the day's closes with source first). IPO listing stories get a listing card from `data/ipos.json` (fill issuePrice and listingPrice). Without these, the cover is an illustration — never add numbers that are not verified.
- **Hindi edition (/hi/, owner's request):** in every slot, add a `hi` object to the most important stories: always the lead/overnight wrap, the daily report, the IPO daily update, gold & silver rates, plus the 2–3 biggest other stories (aim 4–6 Hindi stories per market day; 1–2 on weekends). Fields: `title`, `dek`, `body` [..], and where the English story has them `why`, `indiaImpact`, `globalImpact`, `piggy` {happened, matters, watch[]}, `tableTitle`, `changeNote`; plus `seoTitle` (≤ 60 chars), `seoDescription` (140–165 chars) and `tags` (Hindi search phrases such as "शेयर बाज़ार आज", "सोने का भाव आज", "IPO सब्सक्रिप्शन स्टेटस").
  - Write natural, simple Hindi for Hindi readers (as a teacher explains), not word-for-word translation. Keep the words people search in English: Sensex, Nifty, IPO, GMP, QIB, HNI, Q2, company names, tickers. Numbers, dates and figures must be IDENTICAL to the English story; never add a fact that isn't in the English version.
  - When you update an English story (status "update"), update its `hi` text and `hi.changeNote` in the same run so both languages match.
  - The build makes /hi/news/<id>/, /hi/ home, Hindi sections, /hi/rss.xml, hreflang links, the Hindi news sitemap and the Hindi data pages /hi/gold-rate-today/, /hi/silver-rate-today/ and /hi/ipo/ (from data/rates.json and data/ipos.json) automatically, so keeping those data files fresh updates both languages.
- **Official sources first for ALL market data (owner's rule, 22 Oct).** Before any news site, try in this order and say in the run report which worked:
  - Index closes/OHLC: NSE daily index file `https://archives.nseindia.com/content/indices/ind_close_all_DDMMYYYY.csv` (also `nsearchives.nseindia.com/...`), BSE index pages.
  - FII/DII: NSE `https://www.nseindia.com/reports/fii-dii` (table is script-loaded; read it only if the fetch returns numbers) → NSDL FPI daily `https://www.fpi.nsdl.co.in/web/Reports/Latest.aspx` (check the date shown; it can be stale) → only then 5paisa/Trendlyne/news, labelled "as reported by <source>".
  - Results: NSE filings (see next rule). Never bypass access controls, cookies or protected APIs. If an official URL needs the owner's fetch approval, list it under "Needs approval" in the run report.
- **Company results: official exchange filing first (owner's rule).** For every quarterly result, take the numbers from the company's own filing on NSE, then cite news only as secondary context. How:
  1. WebSearch `site:nsearchives.nseindia.com <NSE SYMBOL> <DDMMYYYY of today>` or `nsearchives.nseindia.com <SYMBOL> integrated filing` / `QuickResults` / `Outcome`.
  2. Best: the **iXBRL integrated filing** (`nsearchives.nseindia.com/corporate/ixbrl/INTEGRATED_FILING_INDAS_..._iXBRL_WEB.html`) — WebFetch it and read revenue from operations, total income, net profit, profit attributable to owners (figures are usually in ₹ lakh: divide by 100 for ₹ crore; state consolidated vs standalone). Also usable: `nsearchives.nseindia.com/corporate/<SYMBOL>_<date>_...pdf` outcome/results PDFs, and the company's own investor-relations PDF.
  3. Put the filing URL as the FIRST entry in `sources` with name "NSE filing" (or "BSE filing"/"Company investor release") and in the results entry's `noticeUrl`. Compute YoY/QoQ from the filing's own comparative columns.
  4. If no official filing is findable yet (filings can lag search by hours), use two news sources, say "as reported by <source>; exchange filing not yet available", and swap in the filing on the next run (status "update", changeNote "Figures checked against NSE filing").
  - Do NOT scrape nseindia.com/bseindia.com app pages or APIs (JS/cookie-gated; BSE PDFs refuse automated fetches). Use only publicly linked archive files. Never bypass access controls.
- **Verify:** prefer primary sources (NSE/BSE, filings, RBI, SEBI, PIB, offer documents). For significant or disputed figures, confirm with a second credible source. Never invent prices, moves, subscription numbers, results, quotes, analyst views or links.
- **No near-duplicates:** before writing, check the newest ~60 posts. If a story on the same topic was published earlier the same day, **update that file** instead of adding a new one: refresh the facts, set `updatedAt` (now), `status: "update"` (or `"developing"` for a fast-moving event) and a one-line `changeNote` saying what changed. A new file is right only for a new day or a genuinely new development.
- **Label uncertainty:** grey market premium, social-media posts, forecasts and brokerage estimates must be named as such with their limitation. Mark preliminary or changing information in the text ("provisional", "as of 3 pm").
- **Every story needs** `seoDescription` (140–160 chars, plain summary with the key number), `coverAlt` (one sentence describing the cover, e.g. "Cover graphic: Nifty -0.34%, smallcaps sink 2.37%"), and the usual SEO fields. The AI-transparency footer is added automatically.
- **Verification gate:** if a story's key fact, date or market figure cannot be confirmed from the sources, do not publish that story (or that figure); list it under "Needs verification". Never fill a gap with an estimate. Publishing fewer, accurate stories is always better than a fixed number.
- **Never call data "live":** TotalMarket has no live data feed. Label figures "as of <time> IST", "close" or "intraday (source, time)"; in `tickerAsOf` write e.g. "As of 12:00 IST, delayed" rather than "Live".
- **SEO fields:** `seoTitle` at most 60 characters (put the main search phrase first; the site name is added only when it fits); `seoDescription` 140–160 characters. One `<h1>` per page is automatic. Don't create new pages for slight keyword variations: link to the existing data pages (/nifty-50/, /global-indices/, /gold-rate-today/, /silver-rate-today/, /fii-dii-data/, /ipo/) from the story body text where relevant instead.
- **End-of-run report in chat:** after publishing, post a short edition status via SendUserMessage: edition date and slot, market status (pre-market/open/closed/holiday), research as-of time, lead headline, number of stories (new vs updated), and a **"Needs verification"** list of anything left out because it couldn't be confirmed (or "None"). Never say something is published unless the push succeeded.

### Boss Piggy explains (site mascot and guide)
Boss Piggy is TotalMarket's friendly market guide (image in `assets/piggy/`, original in `design/boss-piggy-original.png`; never redraw or restyle him). On the most important 2–4 stories of each run (always the lead, the IPO daily and the daily report), add a `piggy` object: `{"happened": "...", "matters": "...", "watch": ["...", "..."]}`. Rules: `happened` restates only verified facts from this story with their numbers; `matters` explains in plain words why it matters to an ordinary Indian investor or saver; `watch` lists 2–3 concrete, dated upcoming events or data from the sources (results dates, IPO dates, policy meetings, data releases). He never tells readers to buy, sell or hold, never predicts or promises moves, never adds numbers that are not in the story, and labels anything provisional. Don't add `piggy` to every story.

## 6. Meta
Update `data/meta.json`: editionLabel, updatedAt, nextUpdate (next slot that will actually run), ticker (Sensex, Nifty 50, Bank Nifty, USD/INR, Gold, Silver, Brent, US 10Y, Nasdaq, DXY; verified only), tickerAsOf. Keep `history`.

## 7. Check (offline pre-check in the research workspace)
The research workspace cannot reach publisher pages from code, so it never builds or publishes. For each job run `python3 -m pipeline check pipeline/inbox/<file>.json` (stages 1–5 in a temporary copy, remote source audit skipped, nothing written to the repo). Fix every FAILED job before committing. Look at the cover preview path it prints. If the build would print a **WARNING** about the market calendar or corporate events, fix that data file in this run.
**Evidence must be copied word for word from the source page** (the publish queue fetches the page and requires the exact quote) and each source needs its real publication time from the page. Prefer sources that serve plain HTML (no paywall, no script-only pages); a live blog entry can scroll away, so quote it only when nothing more stable exists.

## 8. Publish (publish queue on GitHub Actions)
Commit only job files and data files, then push: `git add pipeline/inbox data/*.json && git -c user.name="TotalMarket Bot" -c user.email="noreply@anthropic.com" commit -m "<editionLabel>: <N> jobs" && git push origin HEAD` (on rejection: `git pull --rebase origin main`, push again). **Never commit `docs/`, `data/posts/` or `pipeline/runs/` from the workspace, and never run `build.py` or `pipeline publish` there** (a local rebuild fails the source gate and would drop live stories). The push starts `.github/workflows/publish-queue.yml`: it re-runs every job with the remote source audit, publishes all READY jobs in one gated build, archives them to `pipeline/archive/`, retries failed jobs at 10:05, 17:05 and 00:05 IST, and checks each new page on the live site. After pushing, check the run: `gh api "repos/Niftykingz/TotalMarket/actions/runs?per_page=5" --jq '.workflow_runs[]|select(.name=="Publish queue")|[.status,.conclusion,.head_sha[0:7]]|@tsv'` and, when it finishes, open each new article URL. Report published / failed jobs (with the queue's reason) in the run report; a failed job stays in the inbox — fix its evidence and push again, or list it under "Needs verification". The scheduled message only starts this workflow; it never publishes by itself.

## 9. Scheduling
Runs are started by the recurring scheduled tasks; do not book follow-up runs with `send_later`. The publish queue also retries failed jobs and refreshes time-based pages at 10:05, 17:05 and 00:05 IST.
